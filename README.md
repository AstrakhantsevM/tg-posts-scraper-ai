# tg-posts-scraper-ai

**Парсер Telegram-каналов с AI-суммаризацией через DataBatcher.**  
Собирает посты, прогоняет их через LLM пакетами и собирает итоговый дайджест — без ботов, без API Telegram.

---

## Что умеет

- Скрапит публичные Telegram-каналы через web-интерфейс (без токенов и selfbot'ов)
- Разбивает большой массив постов на **батчи** и обрабатывает каждый LLM отдельно
- Финальный батч получает особый промпт-агрегатор и складывает части в единый дайджест
- Работает по именованным **пресетам** — меняешь один параметр, получаешь другой режим работы
- Три чётких фазы: **scrape → process → report** — каждую можно запускать независимо

## DataBatcher — сердце AI-слоя

Ключевая особенность проекта. Когда постов много, контекстное окно LLM не резиновое — DataBatcher решает эту проблему через стратегию **map → reduce**.

### Принцип работы

```
Посты за период
      │
      ▼
┌─────────────────────────────────────────────────────┐
│                    DataBatcher                       │
│                                                      │
│  posts = [p1, p2, p3, ... p_N]                      │
│                                                      │
│  chunk_1 = posts[0  : BATCH_SIZE]                   │
│  chunk_2 = posts[BATCH_SIZE : 2*BATCH_SIZE]         │
│  ...                                                 │
│  chunk_K = posts[(K-1)*BATCH_SIZE : N]  ← последний │
└──────┬──────────┬──────────┬─────────────┬──────────┘
       │          │          │             │
       ▼          ▼          ▼             ▼
  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌──────────────┐
  │ Промпт  │ │ Промпт  │ │ Промпт  │ │  Промпт-     │
  │ батч #1 │ │ батч #2 │ │ батч #3 │ │  агрегатор   │
  │         │ │         │ │         │ │  (финальный) │
  │ «Вот    │ │ «Вот    │ │ «Вот    │ │ «Объедини    │
  │ первая  │ │ вторая  │ │ третья  │ │ все части    │
  │ часть…» │ │ часть…» │ │ часть…» │ │ в дайджест»  │
  └────┬────┘ └────┬────┘ └────┬────┘ └──────┬───────┘
       │           │           │              │
       ▼           ▼           ▼              ▼
  [summary_1] [summary_2] [summary_3]  [ИТОГ ИТОГОВ]
                                              │
                                              ▼
                                       _04_01_reporting
                                       (финальный отчёт)
```

### Почему промпты разные

| Шаг | Тип промпта | Задача |
|-----|-------------|--------|
| Промежуточный батч | `batch_prompt` | Извлечь ключевые темы и факты из куска постов |
| Финальный батч | `final_prompt` | Агрегировать partial summaries в связный дайджест |

Это позволяет обрабатывать **любое количество постов** без ограничений по размеру контекстного окна — каждый LLM-вызов получает дозированный объём текста и возвращает сжатую версию, которая идёт в следующий шаг.

## Три фазы конвейера

### 1. `scrape.run(ctx)` — сбор данных

Обходит каналы из `_01_03_data/sources`, собирает посты за нужный период и сохраняет сырые данные локально.

### 2. `process.run(ctx, target_date=None)` — AI-обработка

Запускает DataBatcher: загружает сохранённые посты, нарезает на батчи, последовательно вызывает LLM с меняющимися промптами и складывает partial summaries.

Параметр `target_date`:
- `"YYYY-MM-DD"` — обрабатывать посты за конкретный день
- `None` — взять свежайшую доступную дату

### 3. `report.run(ctx, target_date=None)` — отчётность

Берёт результаты из фазы process и формирует финальный документ (дайджест, markdown-отчёт и т.п.). Та же логика `target_date`.

> Фазы изолированы — можно перезапустить только `process` или только `report` без повторного скрапинга.

## Пресеты

Всё поведение системы задаётся пресетом. Пресет — это именованный конфиг, который определяет:

- какие каналы скрапить (`sources`)
- размер батча и стратегию нарезки
- какие промпты использовать
- формат итогового отчёта

```python
# main.py
preset = "weekly_summary"
main(preset_name=preset)
```

Добавить новый режим = добавить новый пресет в `_01_02_configs/presets.py`. Переключение между ежедневным брифингом, недельным дайджестом или тематической выборкой — это смена одной строки.

---

## RunContext

`RunContext` — центральный объект, который живёт весь прогон. Он создаётся из пресета и передаётся во все три фазы, обеспечивая единое место хранения конфигурации, путей к данным и параметров LLM.

```python
ctx = RunContext.from_preset(preset)
# ctx знает: какие каналы, какие промпты, куда писать, с какой датой работать
```
